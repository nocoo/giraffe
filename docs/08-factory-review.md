# 08 — 软件工厂独立审查与验证

2026-09-16：由 **Grok CLI（grok-4.5）** 与 **Pi CLI（GPT-5.6-terra）** 分别独立审阅源码、测量契约和调查摘要。两者只读，没有执行修改。Pi 使用临时会话配置连接可用模型，没有修改本机全局模型配置。原文仅保留最终审查文本：本地 `.factory-cache/grok-findings.md` 与 `.factory-cache/pi-findings.md`。

## 已处理意见

| 来源 | 有效意见 | 最终处理与验证 |
| --- | --- | --- |
| Grok | 超大 Issue/PR 保留最早 5,000 条会偏离近期工作 | 改为 updated 降序，仍完整分页；不按创建时间提前停止。超限显式 limited，优先保留最近更新记录。分页与容量测试覆盖。 |
| Grok | 无效 package.json 卡住整个调查 | 仅将该仓依赖证据标为 unavailable，继续其他资源；已增加解析失败与推进游标测试。 |
| Grok | pending/partial 提交绘为真实零 | 日历/吞吐缺观测时为空态，散点与 sparkline 排除未观测提交，数字用 `—`。 |
| Grok | 合并/关闭日的明细与吞吐不一致 | merged 日筛选和排序使用 mergedAt，closed 使用 closedAt；其余按记录时间。UTC 日期与时区偏移回归测试。 |
| Grok | CI 分片与 until-1s 存在亚秒边界遗漏 | 查询覆盖到 until，子范围边界重叠，最终按全局左闭右开窗口筛选并按 run ID 去重；亚秒与上限分片测试。 |
| Grok | 多仓声明相同 npm 包名会指错引用目标 | 仅唯一包名映射可建边，歧义包名不推断；重复名称测试。 |
| Grok | Actions 与 alerts 的 A/A 短码混淆 | 改为唯一 C/I/PR/CI/R/A/D，并保留完整 aria-label。 |
| Grok | CI 部分覆盖、日历选择与明细筛选语义不清 | CI 明示观测样本及完整仓库覆盖数；选日只高亮账本，文案明确与明细过滤分开。 |
| Grok | 散点下钻缺直接键盘入口 | 保留等价仓库表，图表 hint 明确键盘入口；表格按钮可用键盘操作。 |
| Grok | 空仓仍查询 null:package.json | 没有固定头时直接保存空依赖证据；测试确认零网络请求。 |
| Pi | 分片中途 403/404 后把不完整时间子集标成不可用 | 已取得记录时标为 limited，记录失去权限原因并清空待取范围；无记录才是 unavailable。分片中途拒绝的回归测试。 |
| Pi | 截断提交数与完整数视觉相同 | 单仓提交及不完整的提交/合并/发布汇总显示 `≥` 观测下界；真正零、未知与下界分开。 |

Grok 的性能观察（明细最多解析 1.2 MB、采集批次会更新图表）作为明确有界限制记录在 06；当前仓库表只渲染 25 行、明细只渲染 100 行，ViewModel 使用 memo。另完成路由懒加载，主入口 382.68 kB、最大共享图表 chunk 288.35 kB，构建不再报 500 kB 警告。Pi 未提出额外性能或安全问题。

审查未发现 PAT 被写入快照/响应、外部分页 URL 注入、越过 Access/Origin、跨账号响应回填或缺少工厂响应 no-store 的问题。额外测试覆盖 D1 租约、跨调查 runId、首次重启失败保留旧快照，以及原子 URL 参数更新。
